*[Read in English](README.md)*

Headless-браузер, который выполняет JavaScript, но ничего не отрисовывает, и
ридер, превращающий готовую страницу в Markdown.

Он существует потому, что агенты платят полную цену Chromium — layout, каскад
стилей, композитинг, GPU-процесс, ~300 МБ резидентной памяти — просто чтобы
получить текст. Ничто из этого на текст не влияет. Убрав это, получаем
браузер, который умещается в 5 МБ бинарника и рендерит клиентскую страницу за
единицы миллисекунд.

```
$ mar read https://example.com/spa-page
# Deploying without downtime

Rolling deploys work by never taking the whole fleet out of rotation at once…
```

## Во что это обходится

Замеры на Mac с чипом M-серии, release-сборка, одна страница на процесс.

| | mini-agent-reader | Headless Chromium |
|---|---|---|
| Бинарник | 5 МБ | ~150 МБ после установки |
| Пиковый RSS, обычная страница | 6–7 МБ | 250–400 МБ |
| Пиковый RSS, большая страница (Wikipedia) | 19 МБ | 400+ МБ |
| Рендер локального SPA | 4 мс | 300–800 мс |
| Холодный старт | ~2 мс | 150–400 мс |

Причина такой разницы в рендере — виртуальные часы. Страница, растянувшая
работу на три секунды через `setTimeout`, «устаканивается» за микросекунды,
потому что время идёт вперёд только тогда, когда больше нечего исполнять.

## Из чего это состоит

Шесть крейтов, каждый пригоден для использования отдельно.

- **`mar-dom`** — парсинг HTML и arena-DOM. Узлы лежат в плоском `Vec`,
  адресуются 32-битным индексом, без подсчёта ссылок на каждый узел. Сопоставление
  CSS-селекторов делегировано `selectors` из Servo, так что `:has`, `:is` и
  `:nth-child` работают.
- **`mar-js`** — QuickJS с DOM-биндингами, event loop на виртуальных часах и
  JavaScript-prelude, который достраивает окружение браузера.
- **`mar-net`** — HTTP с заголовками «как у браузера», определение кодировки
  по алгоритму спецификации HTML и слой политик, блокирующий приватные адреса.
- **`mar-extract`** — определение статьи в духе Readability, метаданные,
  Markdown.
- **`mar-cdp`** — эндпоинт Chrome DevTools Protocol, поэтому существующий код
  на Puppeteer, Playwright и chrome-remote-interface может управлять этим
  браузером без изменений.
- **`mar-cli`** — бинарник `mar`, HTTP-сервер и CDP-сервер.

## Устройство

**Без рендерера.** Нет layout, нет каскада стилей, нет отрисовки. Каждый блок —
нулевого размера в начале координат, `getComputedStyle` возвращает то, что
сказано в инлайн-стиле, а `IntersectionObserver` никогда не срабатывает. Это и
есть вся экономия, и поэтому скриншоты — вне области применения.

**Тонкая нативная поверхность, толстый JS-prelude.** Rust реализует только то,
что требует доступа к документу, состоянию страницы или сети — около тридцати
функций. `Event`, `classList`, `style`, `fetch`, `XMLHttpRequest`, `URL`,
`localStorage` и всё остальное написаны на JavaScript поверх этого. Закрыть
пробел для сайта, который не рендерится, обычно значит поправить `prelude.js`,
а не движок.

**Виртуальные часы.** Таймеры лежат в куче, упорядоченной по времени
срабатывания. Когда микрозадачи вычерпаны и нет незавершённых сетевых
запросов, часы перескакивают к следующему таймеру. Реальное время ожидания
никогда не тратится. Таймеры за горизонтом не срабатывают вовсе — это не даёт
опрашивающей (polling) странице «жить» бесконечно.

**Движок никогда сам не открывает сокет.** Он вызывает `NetworkProvider`,
который предоставляет хост, — так вся политика живёт в одном месте, а тесты
идут офлайн, на заранее заданных ответах.

**Всё ограничено.** Потолок кучи JS, потолок стека, бюджет по реальному
времени, горизонт виртуального времени, бюджет вызовов таймера, бюджет
подгружаемых ресурсов, бюджет байт консоли. Страница, которая ведёт себя
плохо, обрезается и помечается как обрезанная.

## Установка

Готовые бинарники для Linux (x86_64, aarch64), macOS (Intel, Apple Silicon) и
Windows прикладываются к каждому
[релизу](https://github.com/Blynskyniki/mini-agent-reader/releases/latest).
Скачайте архив для своей платформы, распакуйте и запустите `mar`.

Либо соберите из исходников:

```bash
cargo build --release          # ~30 c, из системных зависимостей нужен только Cи-компилятор
```

## Использование

Прочитать страницу как Markdown:

```bash
mar read https://example.com/article
```

С метаданными как YAML front matter или единым JSON-объектом:

```bash
mar read https://example.com/article --format full
mar read https://example.com/article --format json
```

Пропустить выполнение JavaScript, когда страница отрендерена на сервере, — так
намного быстрее:

```bash
mar read https://example.com/article --no-js
```

Получить итоговый HTML и отчёт о стоимости в stderr:

```bash
mar fetch https://example.com/ --report
```

Задать вопрос уже «устаканившейся» странице:

```bash
mar eval https://example.com/ "[...document.querySelectorAll('h2')].map(h => h.textContent)"
```

Поднять сервер:

```bash
mar serve --bind 127.0.0.1:3000 --workers 4
```

```
POST /read   {"url": "...", "max_chars": 4000, "images": false}
POST /html   {"url": "..."}
POST /eval   {"url": "...", "expression": "..."}
GET  /health
```

Каждый воркер рендерит по одной странице за раз. Двенадцать одновременных
запросов к локальной странице на трёх воркерах выполняются примерно за 40 мс.

Либо говорить по протоколу Chrome DevTools — тогда существующий код на
Puppeteer/Playwright указывается на `mar` без изменений:

```bash
mar cdp --bind 127.0.0.1:9222
```

## Доверие TLS

Некоторые сайты — в том числе `gosuslugi.ru` и `mos.ru` — предъявляют
сертификаты, выпущенные удостоверяющим центром Минцифры России; такой корневой
сертификат не встроен ни в один браузер и ни в одну ОС. `mar` включает его в
поставку, но обращается к нему только после того, как публичный набор
доверенных корней уже отверг цепочку сертификатов, — поэтому он может спасти
соединение с сайтом, который иначе не открылся бы, и никогда не переопределяет
проверку для сайта, который и так работает. `mar certs` показывает, что зашито
в бинарник; флаги `--trust public-only|combined|none` и `--ca-bundle <файл>`
меняют политику доверия.

## Безопасность

Запросы к loopback-, приватным, link-local и другим зарезервированным
диапазонам адресов по умолчанию отклоняются, включая `localhost`, и разрешены
только `http` и `https`. Сервис рендеринга получает URL, который выбрал
вызывающий, а затем выполняет скрипты, которые выбирают ещё что-то; без этой
защиты `http://169.254.169.254/` от имени вызывающего читает облачные
креды. `--allow-private` снимает ограничение для локальной разработки,
`--allow-host` сужает выборку до заданного набора доменов.

Скрипты не могут сами никуда перенаправить хост. Присваивание
`location.href` фиксируется и исполняется лишь потому, что так сделал бы
браузер, — с ограничением в три перехода и с обнаружением циклов, а
кросс-доменные запросы подресурсов отклоняются.

## Ограничения

Осознанные и намеренные:

- **Нет скриншотов и PDF.** Для этого нужен рендерер, а его в проекте нет
  специально.
- **Нет подмены TLS-отпечатка.** Заголовки выглядят как у Chrome, а
  TLS-рукопожатие — нет. Сайты за интерстициальной проверкой всё равно её
  покажут.
- **Нет загрузчика модулей.** Скрипт с `type="module"` компилируется и
  выполняется, но `import` другого URL завершается ошибкой. Рантаймы страниц,
  которые бандлятся так, залогируют ошибку — остальная часть страницы всё
  равно отрендерится.
- **Нет WebSocket, Worker, WebGL, canvas и медиа.** Конструируются без
  исключений и ничего не делают.
- **Кросс-доменные скрипты не загружаются.** Сторонние бандлы — почти всегда
  аналитика и реклама: медленно, и для чтения не дают ничего.
- **Извлечение статьи — эвристика.** Страница без явно выраженной статьи
  помечается `low_confidence: true`, а не «додумывается».

## Тестирование

```bash
cargo test
```

Тридцать девять тестов: структура DOM и round-trip сериализации, семантика
CSS-селекторов, определение кодировки по порядку приоритета из спецификации,
политика от SSRF, извлечение статьи и сквозной рендеринг — включая промисы,
`fetch`, виртуальные часы, изоляцию ошибок и бюджет на «убежавшую» страницу.
Сеть при этом не используется нигде.
